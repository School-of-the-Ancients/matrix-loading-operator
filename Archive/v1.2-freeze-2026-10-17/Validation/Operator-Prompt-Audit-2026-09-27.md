## Two representative prompt shapes and sizes

The two utterances in #116 use **synthetic request-time fixtures** in the same ready AR virtual room with paused Creator Mode, animation and rigid schema version 1, 30 catalog assets, and no pointing/viewer frame. The load turn has an empty scene at revision 17 (637 compact-JSON characters). The move turn is revision 19 with selected `dragon-1`, display name Ice Dragon, a `Flight` loop, pose `(0, 1.5, -2)` and scale `(0.5, 0.5, 0.5)` (1,173 compact-JSON characters). Both have validated Matrix Web/Three.js/WebXR identity. The same enabled-tool fixture contains scene summary, asset listing, animation binding and object move. Counts evaluate the old `send_text` wrapper in `5aefb66^`, `build_matrix_turn_message()` in `c175818`, and the candidate builder against each matching fixture. They are **source-generated examples**, not captured live prompts.

Both old examples begin “Matrix spatial context follows” and repeat the floor-drop and unrelated component/scale explanations. The candidate load example begins “Matrix Operator live contract (supersedes older capability claims)”, identifies Matrix Web in AR with ready room and unverified physical alignment, asks for catalog discovery, and ends with the first utterance in the table. The candidate move example keeps that live identity, asks for a fresh scene and target inspection, omits the load catalog paragraph, and ends with the second utterance verbatim.

The pre-#127 wrapper added the same 1,779-character prose/tag overhead to both turns, including `matrix_set_physics` and unrelated component/scale instructions. The candidate starts with “Matrix Operator live contract (supersedes older capability claims)” and adds 1,248 characters for load or 988 for move: the first has catalog discovery; the second has target-inspection guidance. Both state Matrix Web/AR identity, ready room and paused Creator authority, then serialize context and place the complete utterance after `User request:`. All characters in these fixtures are ASCII, so counts equal UTF-8 byte counts and fit the existing 16,000-character limit. Neither example implies that a live Agent made a correct choice or obtained a receipt.
