## Reference outcome and existing foundations

**Open the existing world, converse with Galileo, predict a change, try one
exhibit, discuss the observed result, then save and return.**

Double each length of the same block and explain the **8× mathematical volume
ratio**. Use School's existing lesson and live Codex text adapter. A readable
conversation surface is sufficient; a generic Matrix mentor entity/avatar is
optional and requires no Citizens simulation.

## Integration contracts

**Session ownership.** School supplies conversation, teaching, provider and
durable learner evidence. Matrix supplies optional world presentation and
supported entity state. One foreground guide is enough; no second transcript
store, general Citizen memory or new simulation is required.

**Experiment scope.** The initial capability requires a built-in virtual-floor
block in supported virtual-room mode: desktop and Quest VR first. AR room-surface
experiments need separate support/evidence. Preserve ordinary AR regressions
without claiming this lesson measures a physical table. User-facing lengths use
feet; retain established contract units.

**Observed outcomes.** Distinguish suggestion, proposal, dispatch, receipt and
current observation. A model reply cannot advance the lesson or establish that
a mutation succeeded. Repeated clicks/polls create no duplicate action or event.

**Authority.** School's Matrix client currently reads and proposes; the human
owner reviews and Applies on the PC's /clients page. The reference integration
retains that human decision while making bounded review reachable in the headset.
Roles and Create/Play grant nothing. Use authenticated
Operator transport for review; keep the companion and local-only client API on
the PC. Add a bounded presentation bridge, not arbitrary remote client access.
Any later delegated exhibit control needs the explicit grant/policy described
in the [UX plan](Matrix-Modular-UX-Plan.md#guide-interaction-and-authority).

**Recovery.** School history survives service restart; pairing credentials and
Matrix's client request/baseline ledger do not. The common virtual-room ID is
not a unique saved-world ID. Verify checkpoint/archive identity, exact exhibit
state and School mentor/session references, plus any optional avatar ID. A fresh
pairing requires an owner-reviewed rebind and new baseline request chain; add
that minimal adapter operation if absent. Retain old evidence as historical and
show what the new Reset returns to. Re-observation restores neither old
authority nor the old baseline. Runtime lease and saved-world identity remain
distinct.

**Save scope.** Desktop full PC checkpoints, XR full browser checkpoints and PC
scene-only backups differ. Name and verify the supported recovery path alongside
School's records; this integration does not perform a general save migration.

Fresh observation establishes current state; reviewed rebind establishes a new actionable baseline after lease/pairing change. Missing records never trigger replay. |
