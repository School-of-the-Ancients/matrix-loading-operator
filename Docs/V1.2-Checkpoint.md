For startup use the bundle's `RELEASE-README.md`, [release runbook](../Tools/README-WebXR-Release.md), [Agent guide](../ControlService/AGENT_PORTAL.md), [Quest controls](../WebRuntime/README.md#quest-controls-faq) and [host runbook](Persistent-World-Host.md). Codex/provider credentials stay PC-side. The interactive owner enters its service token in its own `/web/` tab; a hosted visitor receives only its view token. Reviewed approvals need an interactive terminal. Save the world and copy unsent text before refresh/version switching; refresh requires token re-entry.

World saves, exact registered GLBs/panoramas, content configuration/cache, Agent sessions and optional speech/models remain external data. The public ZIP excludes private worlds/catalogs, credentials, room imagery/scans, transcripts, model weights, Blender installation/job state and editable `WebRuntime/art` examples. No portable demo world is included.

## Reproduce the published package

Use an isolated checkout of the frozen commit and its original builder, with the tool versions recorded in the attached manifest. From that checkout, write to a new local output directory:

```sh
python Tools/Build-WebXR-Release.py --version v1.2.0 --commit 858d486e9ee8507af36e2a05d78f1d34fc9ca2b0 --output ./work/reproduce-v1.2.0
```

The builder exports committed source, runs `npm ci` and Vite, installs locked production dependencies, creates a deterministic ZIP, verifies extracted file hashes and runs isolated service/host/route/token smokes. It does not tag or publish. The version label and Python/Node/npm versions appear in generated output; preserve the original manifest's `build_tools` and `builder_sha256` alongside the lockfile before expecting byte equality. External inference environments are not frozen by the ZIP.

Keep active source/build/test files and the three root launch/setup scripts. The builder also requires root README/VISION/ARCHITECTURE/ROADMAP/LICENSE; `Docs/{Persistent-World-Host,Citizens-Shared-World,Versions-And-Submissions,Control-Page-Routes,Matrix-Environments}.md`; `Examples/block_scale_client.py`; and `Validation/client-api-v1-fixtures.json`. The fixture is also a service-test input. `Validation/test_prefab_previews.py` requires its sibling `Add-Prefab-Previews.py`; service checkpoint tests use `WebRuntime/test/fixtures`. These are not disposable progress outputs. Citizens remains imported by the current browser, save adapter and host; logical module ownership does not permit deleting that code from v1.2.
