# AI Citizens in the Matrix Web world

The [#20](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/20) shared-world slice builds on the isolated [Citizens desktop fixture](Citizens-Desktop-Demo.md). The ordinary `/web/` page has an opt-in **AI Citizens** panel. It runs the same two-resident simulation through the page's existing `MatrixWorld`, `MatrixView`, and `MatrixBridge`. **Start here** creates the original chair/table/two-orb fixture only on an empty desktop virtual floor. The selected-furniture candidate described below instead keeps an existing scene and binds one selected built-in chair or table while adding two orb residents. The Agent Portal is not used for resident decisions or given to residents. The [#19](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/19) candidate adds the finite social session described below to the reservation lifecycle.

The live-revisions candidate lets a finite **Offline commands** proposal edit
an unrelated selected scene object while residents continue moving. Turn off
**Automatically apply safe scene requests** if you want to inspect the exact
command before pressing **Apply proposal**. An edit aimed at a resident becomes
stale when its observed pose changes. A queued resident edit is checked again
by the browser before execution; later commands in the same reviewed batch are
skipped if a prior command fails. AI, visual review, voice, and game planning
check all resident poses through Apply; pause Citizens for those paths because
implicit actor dependencies can change before browser execution.
The runtime also checks the current measured obstacle line before a resident
can receive a station-use benefit. See the [isolated browser record](../Validation/citizens-live-revisions-browser.json)
and [current checkpoint](Current-Checkpoint.md) for the verified scope.

The registered-GLB readiness candidate requires the actual Three.js view to
load and measure each registered GLB obstacle before Citizens trusts its
catalog footprint. A failed load or catalog/scene change makes routes
unavailable until the current model verifies again. The panel shows that
reason and disables Run/Step; a running simulation pauses before another tick
and releases active or queued station work. A content-identical redraw during
ordinary resident movement keeps the measured-footprint evidence. The
`MatrixWorld.interact` clearance check also refuses a nearby unverified GLB
and any catalog GLB with animation clips because no safe swept footprint is
available for finite use.
Catalog GLBs with animation clips are refused for Citizens navigation until a
measured animation envelope is available, including clips that auto-loop or
play on selection.
To try this with an authored registered GLB, load it beside a selected built-in
chair in an isolated `/web/` virtual room, wait until its model is visible,
then choose **Use selected chair or table** and run the two residents. Save a
named PC world checkpoint, reload, wait for the model to verify, and step.
The [browser evidence](../Validation/citizens-glb-readiness-browser.json) used
the [static Blender probe fixture](../WebRuntime/test/fixtures/static_blender_probe.glb)
and a deliberately mismatched catalog footprint to exercise the refusal,
then restored measured bounds for a seeded chair queue and restart replay.
It also records a live mismatch that released Bo's active chair claim. This is static desktop obstacle
readiness, not a general GLB interaction definition or Quest check.

## Try it safely

From the repository root, build and use an isolated ControlService port and scene directory:

```powershell
npm.cmd --prefix WebRuntime ci
npm.cmd --prefix WebRuntime run build
$demoRoot = Join-Path $env:TEMP 'matrix-citizens-shared-world'
$scenes = Join-Path $demoRoot 'scenes'
$assets = Join-Path $demoRoot 'web-assets'
New-Item -ItemType Directory -Force -Path $scenes,$assets | Out-Null
python ControlService/server.py --host 127.0.0.1 --port 19840 --scenes $scenes --web-assets $assets
```

Open `http://127.0.0.1:19840/web/` in a separate browser profile with no saved world for that origin. Choose a seed and click **Start here** in the AI Citizens panel, then **Run** or **Step**. The panel shows each resident's need levels, activity, recent outcome, reservations, social session, relationship, and decision log. **Stop Citizens** requires a second click within ten seconds; it removes the simulation state but leaves its objects in the scene. Existing worlds cannot start this fixed-position scenario until the user explicitly chooses a separate empty world.

For the selected-furniture candidate, use the ordinary `/web/` desktop virtual room with an existing built-in chair or table, select that object, then choose **Use selected chair or table** in the AI Citizens panel. This is an explicit alternative to **Start here**: it does not clear the existing scene, move or duplicate its furniture, or start the separate `/web/citizens.html` fixture. It adds two ordinary orb residents and binds the selected object's existing ID as a rest or food station. Only the selected built-in furniture is bound as a Citizens station in this path; a GLB that merely looks like a chair or table is not eligible. Existing scene objects remain. Finish or remove an active game before starting Citizens.

The selected path is bounded to the desktop virtual floor. It refuses an absent or incompatible selection, an already active Citizens simulation, an active game, moving or unsupported scene geometry, and placement or movement that cannot meet the current room and clearance limits. Residents travel by finite, observed MatrixWorld moves; a blocked or unreachable route is reported instead of crossing known obstacles or granting the expected need benefit. The capacity-one claim, wait, timeout, cancellation, and matching interaction receipt rules still apply. Browser reload and named PC whole-world restore carry the scene object IDs and Citizens state together; restore validates the saved bindings before replacing the active world. The panel log and feedback show refusals and interrupted actions. These are candidate behavior descriptions, not new Quest wearer evidence.

Navigation uses the current built-in measured footprints on one level virtual floor. The two orb residents retain their 0.7 scale; resizing or elevating one makes its binding incompatible with the fixed clearance calculation. Selected furniture and other scene objects must be floor-aligned, upright, and have stable measured bounds. V4 exploration goals are local to each resident and bounded by the virtual floor; older checkpoint versions retain their original narrower target bounds during validation. An unavailable route fails explicitly, and the panel performs its full route search only after **Use selected chair or table** is clicked.

The [selected-furniture browser record](../Validation/citizens-selected-furniture-browser.json) and [screenshot](../Validation/citizens-selected-furniture-browser.png) use a separate loopback service. The ordinary planner added a chair and wall, the Three.js view selected the chair, and **Use selected chair or table** added only two orbs. Bo's observed rest outcome and Ada's queue appeared at minute 23. A later completed conversation carried receipt `citizens-29-social-37-242` and raised the relationship score to 55. Reload retained paused minute 319; a named PC checkpoint restored its four exact object IDs, chair claim, and Citizens state, and the next step replayed the same need change. The final WebRuntime suite passed 223/223, ControlService passed 658/658, and Vite built. The obstacle detour and blocked-start cases were verified in focused unit tests; the browser scene's wall remained a separate authored object and was not used to claim full #15 navigation acceptance.

This advances a narrow part of [#15](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/15). Its broader contract remains open: versioned object-advertised interaction definitions with capabilities, predicates, approach/use poses, capacity and effects; independently tested reachability for supported geometry and changing routes; navigation readiness and geometry versions; one motion authority across decorative/root motion; save/load reporting for missing dependencies; and obstacle, occupied, removed, and unsupported acceptance fixtures. This candidate supports explicitly selected built-in furniture in a bounded virtual room. It does not establish arbitrary authored GLB affordances, real-room navigation, a general NPC path service, or complete #15 acceptance.

The usual browser world save carries a version 3 envelope when Citizens is active. Existing version 2 scene/game saves still load and retain their original shape. The manual browser **Save world** checkpoint and named **PC world checkpoint** include the Citizens clock, IDs, needs, current intent, claims and wait queue, RNG state, and bounded log alongside scene/game state. PC save pauses the simulation before capturing it; click **Run** after restore to continue. After closing and reopening the browser, wait for **Operator connected** before using PC save/restore; ControlService's single runtime lease can take up to 15 seconds to pass to the new client. Browser-local recovery does not require the PC lease.

An authored move of a bound resident or station cancels the affected activity or wait, releases its claim, and pauses Citizens. A running station component or active transform behavior also invalidates that binding, so the simulation cannot grant a need benefit at a stale visual position. An incompatible remaining binding blocks invalid browser/PC checkpoint writes; the previous valid browser copy remains available. Undo the edit, restore a valid named PC world checkpoint, or use **Stop Citizens** to keep the edited scene without simulation bindings. Entering AR pauses this desktop simulation and cancels active activities, claims, and queued waits before any AR edits; it remains paused after returning. No Quest simulation acceptance is claimed. Room-origin recovery archives preserve the version 3 virtual world state.

## Bilateral social session candidate ([PR #103](https://github.com/School-of-the-Ancients/matrix-loading-operator/pull/103), #19)

The outer scene/game/Citizens world envelope remains version 3. The nested Citizens state is now **`schemaVersion: 4`**. Valid nested v1 and v2 states migrate on browser restore. A v3 social state migrates only if its retained completed events account for the saved relationship score; otherwise restore reports the missing evidence instead of accepting an unobserved gain. The PC service accepts all four exact shapes without rewriting an older checkpoint file. V3 introduced one bounded active session, matching session IDs on both residents, a bounded event list, a pairwise relationship score, and the next invitation tick. V4 adds a rolling, bounded per-pair completion ledger with session and receipt IDs and derives the score from it. The `/web/` and isolated inspectors show the offer, accepted session, explicit terminal outcome, receipt ID for an observed completion, and relationship score.

After individual activity has begun, two available residents can initiate a conversation. An authored response uses the saved random state to accept, decline, or leave the offer unanswered. An offer expires after four simulation ticks; an accepted session has a 72-tick deadline. Both residents must still be live, idle, unqueued, and bound to the same session ID at each transition. The initiator travels toward the invitee. At completion, `MatrixWorld` checks the orb's advertised `converse` interaction and observed distance of at most 0.8 m, then returns a receipt carrying that session ID. Citizens checks the exact request, actor, target, kind, session ID, and distance. Only this matching receipt raises both residents' fun and the pair's relationship score. Declines, timeouts, interrupted moves, rejected receipts, deletion, scene replacement, AR entry, and Stop cannot grant that benefit.

The event list records `initiated`, `accepted`, `declined`, `timed_out`, `ended`, and `interrupted` transitions. Its fixed-seed order and active session resume with the scene and simulation checkpoint. The PC validator checks the saved structure and bindings and that each retained `ended` event has a matching completion record. A historical receipt reference documents the browser's local MatrixWorld result, rather than a second PC-side execution or a cryptographic attestation. This is a small authored response and finite interaction fixture. It adds no dialogue service, LLM tick loop, multiplayer session, or general conversation engine.

## Earlier reservation lifecycle candidate (#19)

This earlier slice used a **version 3** scene/game/Citizens envelope and **`schemaVersion: 2`** nested Citizens checkpoint. It added `actionSequence` and `retiredResidentIds`; each active activity has an `executionId`. Each capacity-one station stores `claim: {residentId, executionId, expiresTick}` or `null` and a FIFO `waiters` array of `{residentId, executionId, enqueuedTick}`. The panel shows the claim's execution and expiry, each waiter's queue position and execution, and retired actors or removed fixture resources.

A claim lasts at most **72 simulation ticks** from acquisition. If it expires, that execution fails and releases its claim; a waiting resident can take the next free turn. The head of a station's queue goes first, in deterministic enqueue tick and execution order. A wait expires after **96 ticks**. Cancellation, failed movement or interaction, and AR entry clear the affected claim or wait without granting a need benefit. A station is checked again at use time; only a matching `MatrixWorld` interaction outcome updates the need. These are local simulation ticks, displayed as minutes in the panel, not wall-clock minutes or a PC-service lease.

Deleting a live resident object retires its ID, cancels its activity or wait, and frees its claim. Deleting a station object removes that station and cancels its claimant and waiters. Other residents can keep running on remaining activities and stations; deleting the last resident pauses Citizens. A still-present incompatible object or active transform owner requires recovery; an externally moved compatible object pauses the simulation for inspection. Restoring a checkpoint whose named bindings are missing or incompatible is rejected before replacing the active world. The runtime reconciles a live deletion into a valid Citizens snapshot before saving the edited world, including edits made while the virtual world is paused in AR.

On browser restore, a valid nested **v1** Citizens state migrates deterministically: resident order assigns execution IDs to active activities, each old `holder` becomes a matching claim with expiry at the saved tick plus 72, and wait/retired lists begin empty. Current browser restore migrates valid v1 and v2 states through the intermediate versions to nested v4. A v3 state requires retained completed events consistent with its relationship score before migration. The PC service accepts v1 through v4 checkpoint shapes and preserves a raw older file until browser restore migrates it; it does not rewrite the old file in place. A scene/game-only version 2 world envelope remains scene/game-only.

At this earlier checkpoint, the start flow was still a fixed two-resident, two-station fixture on an empty desktop floor. The v2 validator bounds live plus retired residents to four, live stations to two, and the log to 80 entries. Each activity acquires at most one resource. This earlier checkpoint predates the v3 social session and selected-furniture candidate above; general multi-resource acquisition remains open. Quest simulation and multiplayer networking remain separate work.

## Reservation lifecycle verification

The first edit that removes a bound resident or station also stores the complete prior browser world in a separate **pre-deletion recovery** slot before normal autosave. This covers Delete, Clear, and scene Load. If that backup cannot be verified, both autosave copies stay at their previous values and the page reports the failure. The Citizens panel shows the backup minute and offers **Restore** with a second confirming click; restore validates the full saved world before replacement. After the restored world is saved durably and verified, the slot clears so a later deletion can capture a fresh copy. The manual **Save world** checkpoint is separate and untouched. Scene **Undo** alone can return an object without restoring its retired Citizens binding; use the pre-deletion restore to recover both. Until restored, the slot keeps the first pre-deletion copy, even if the reduced world advances or another object is removed.

Named PC world restore pauses Citizens before loading, blocks its timer and browser autosave while the service exchange is pending, and writes the accepted or rolled-back world after the exchange settles. A delayed rejection regression checks that the staged world never reaches browser storage. At this earlier reservation-lifecycle checkpoint, Operators had to pause Citizens before any scene or game proposal because every resident move advanced the scene revision. The live-revisions candidate above narrows that restriction for finite offline edits to unrelated objects. Its AI, image, voice, and game planning paths remain strict; the demo's autonomous runtime itself does not need a planner request per tick.
