## Virtual-day routines candidate

The `codex/citizens-virtual-day` candidate adds a persisted clock speed and recurring daily routine windows to the existing two-resident `/web/` simulation. One `clockTick` is one simulated minute; day and local clock display derive from `floor(clockTick / 1440) + 1` and `clockTick % 1440`. Use **1×**, **4×**, or **16×** for that many sequential simulated minutes each visible half-second while running. **Step one minute** always advances exactly one. Pause, a hidden browser tab, or closing the page stops advancement, with no missed-time catch-up on return. The selected speed, clock, residents, routine windows, and latest bounded score trace are part of nested Citizens v7 in both browser saves and PC world checkpoints. Valid v1–v6 Citizens saves migrate when loaded; old checkpoint files are not rewritten. The outer world envelope remains v3.

Each resident has up to six daily windows for `rest`, `eat`, or `explore`. Fresh and migrated Ada and Bo have overlapping morning meal/walk windows, daytime exploration, and a rest window crossing midnight, with different weights. While idle, a resident scores eligible active windows using its need deficit, existing preference, travel, weight, priority tier, and station availability. The inspector shows active windows and the latest candidate components. A routine can choose only an existing finite activity: station reservation, navigation, Matrix interaction and observed receipt still decide whether a need benefit is earned. Existing active actions, FIFO waits, and social sessions complete through their existing paths before another idle choice. Windows recur daily; this candidate does not add hard appointments, action interruption, work jobs, an economy, or an LLM request per frame. The panel shows the claim's execution and expiry, each waiter's queue position and execution, and retired actors or removed fixture resources.

A claim lasts at most **72 simulation ticks** from acquisition. If it expires, that execution fails and releases its claim; a waiting resident can take the next free turn. The head of a station's queue goes first, in deterministic enqueue tick and execution order. A wait expires after **96 ticks**. Cancellation, failed movement or interaction, and AR entry clear the affected claim or wait without granting a need benefit. A station is checked again at use time; only a matching `MatrixWorld` interaction outcome updates the need. These are local simulation ticks, displayed as minutes in the panel, not wall-clock minutes or a PC-service lease.

Deleting a live resident object retires its ID, cancels its activity or wait, and frees its claim. Deleting a station object removes that station and cancels its claimant and waiters. Other residents can keep running on remaining activities and stations; deleting the last resident pauses Citizens. A still-present incompatible object or active transform owner requires recovery; an externally moved compatible object pauses the simulation for inspection. Restoring a checkpoint whose named bindings are missing or incompatible is rejected before replacing the active world. The runtime reconciles a live deletion into a valid Citizens snapshot before saving the edited world, including edits made while the virtual world is paused in AR.
