# Matrix v1.3 implementation plan: the first School lesson in WebXR

Planning update: October 17, 2026, America/Denver.

Tracker: [#187](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/187). Status: proposed implementation plan; runtime work has not started from this plan.

## The finish line

**Enter Matrix, meet Galileo, make a prediction, change one exhibit, discuss what actually happened, then save and return to the same lesson.**

Matrix already creates things. The next useful step is connecting that world to a teacher that can use it. This gives School a complete spatial learning experience and establishes the observation/action boundary that future Citizens can reuse.

Start with the existing Block Scale Lab: double each length, observe the same block, and explain the **8× mathematical volume ratio**. Use the existing School lesson and live Codex text adapter. A simple professor representation and readable lesson controls are enough.

## Contracts that keep the work small

**One lesson, one exhibit, one foreground guide.** School owns the teaching, provider and learner record. Matrix owns the world and supported resident identity. Operator executes reviewed work. The first memory comes from School's existing durable evidence; v1.3 does not need another transcript store or a general vector-memory service.

**One experiment truth.** The initial scale capability requires a built-in virtual-floor block in the supported virtual-room mode. Start with desktop and Quest VR. Room-surface experiments and AR-specific lesson behavior need their own support/evidence; preserve ordinary AR regressions without claiming this scale lesson works on a physical table. User-facing lengths use feet; retain established units in contracts.

**One real outcome per request.** Distinguish suggestion, reviewable proposal, dispatch, receipt and observed result. A model reply cannot advance a lesson or claim a mutation succeeded by itself. Repeated polls/clicks must not create another action or event.

**Keep the existing authority split.** School's mentor is read-only; its Matrix client proposes and the human owner Applies. A professor role or Create/Play switch does not grant editing authority. Reuse owner review behind the existing authenticated Operator transport. The local-only client API must not be opened to arbitrary remote browsers to make the XR panel work. Keep the School companion on the PC and add only the bounded presentation bridge needed by WebXR.

**Restore state, then trust current observations.** School history survives restart, but pairing credentials and Matrix's client request/baseline ledger do not. Historical evidence cannot become a new actionable baseline automatically. The common virtual-room ID is not a unique saved-world ID. Verify checkpoint/archive identity plus exact professor/exhibit IDs and state; add the minimum owner-reviewed rebind operation in the School adapter if absent. A fresh pairing starts a new reviewed baseline request chain. Preserve the previous baseline/result as historical, and show what the new Reset returns to. Re-observation alone restores neither old authority nor the old baseline. Keep runtime lease identity distinct from saved world/exhibit identity.

**Preserve save scope.** Desktop PC full checkpoints, XR browser full checkpoints and PC scene-only backups are different today. Name the supported recovery path and verify both products' records; do not relabel all three as equivalent or start a general save migration.

## The next society increment

After the professor loop passes, take a bounded [#29](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/29) slice: **professor + assistant, with different knowledge.**

1. The professor observes an exhibit change.
2. The absent assistant initially does not know it.
3. A recorded conversation transfers that information.
4. The assistant recalls its source and changes one bounded plan.
5. Save/reopen preserves the two identities and supported knowledge.

That is where generic Citizen episodic memory, retrieval and grounded conversation enter. Evaluate witnessed/unwitnessed events, communication, changed goals and recovery; compare matched runs with and without retrieval. Reuse navigation and world execution. Model calls happen on meaningful decisions, within measured budgets.

School learner records stay private to School. Shared resident memory contains only permitted observations. Continuous living for this interactive professor world remains separate [#20](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/20)/[#148](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/148) work. The implemented PC-owned Ada/Bo fixture can continue without visitors; that support does not automatically extend to an arbitrary interactive professor world.

## A project rule that stops the backlog running the project

Use **ROADMAP → #187 → the current bounded issue → a draft PR**.

- Keep one implementation slice active and at most one completed slice awaiting review/validation. Independent review, tests and documentation may run in parallel.
- Every active task names the visible result, owning module, dependencies and “done when.” If it cannot explain how it helps the current finish line, put it in Later.
- Add new ideas to the existing owning issue, or RESOURCES for research. Open a new implementation issue only when there is a distinct selected outcome.
- A hardware block records the exact missing check. Continue independent prepared work without expanding the release or treating the check as passed.
- At the end of a work session, record what changed, evidence, the next task and the real blocker. Reorder deliberately; do not reset the roadmap because a new idea arrived.
