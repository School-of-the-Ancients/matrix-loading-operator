# Procedural creation and Immersive Creator Mode

Status: **merged in [PR #127](https://github.com/School-of-the-Ancients/matrix-loading-operator/pull/127)**, September 26–27, 2026. [Issue #122](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/122) retains the full procedural creation and immersive acceptance. This implementation adds rigid physics, challenge state, live displays, and Creator/Play controls to the same `/web/` Matrix world. The test route and evidence here do not establish that a headset or the user's running service has loaded the merged source.

## What owns the world

`MatrixWorld` still owns scene object IDs, transforms, commands, receipts, and revision checks. The same scene appears through desktop Three.js, WebXR VR, and WebXR AR. PC-local Codex uses the existing Agent Portal and typed Matrix tools; the browser never receives its credentials. Blender/GLB registration, animation, components, Citizens, and older worlds remain supported.

## A generated object that residents can use

The reviewed `curved-bench@1.0.0:curved-bench-v1` source can carry a version-2 `rest` interaction. The descriptor pins the generator ID, version, and source revision, plus floor-local approach/use poses, range, duration, capacity, and energy effect. The PC service independently checks the bench's measured bounds and exact source before queueing or saving it. The Web runtime checks the generated mesh bounds and current recipe before applying it. Other procedural generators and interaction kinds require their own reviewed PC bounds contract. Existing version-1 registered GLB interactions and Blender authoring remain supported.

In paused Creator Mode, create a curved bench through `matrix_create_procedural`, inspect its ID/recipe, then set the reviewed interaction with `matrix_set_interaction`. A compatible parameter revision uses `matrix_update_procedural` and keeps the same object ID and interaction; an incompatible pose or source is rejected before changing the scene. Undo/Redo, browser persistence, and named PC world checkpoints retain the compatible recipe and binding. Select the bench in `/web/` and use **Use selected station** to add the two existing Citizens residents to that world. Their rest need changes only after a checked Matrix interaction outcome. The [isolated browser check](../Validation/Procedural-Citizens-Desktop-2026-09-26.md) records the actual create, revise, Undo/Redo, save/reopen, resident use, and PC restart/restore results.

| Capability | Saved source | Live observation or action |
| --- | --- | --- |
| Procedural construction | `object.procedural` pins generator ID, version, source revision, normalized parameters, seed, and dependencies | `generateProcedural` creates indexed meshes with stable part IDs and measured bounds; generic create/update commands keep the Matrix object ID |
| Creator/Play mode | `creatorMode` in the existing world envelope when changed from the default | Desktop controls and an in-world XR panel switch modes; Play runs the rigid solver and blocks authoring edits |
| Rigid body and gravity | `object.rigidBody`, current scene pose, and optional `rigidGravity` | Rapier owns dynamic motion, static and sensor colliders, contacts, and repeated grab/move/release |
| Challenge | Existing `game` field with version 2 spec, existing object-ID bindings, credited event ledger, progress, and unlocked exit IDs | Sensor or release events update one shared game state; human UI, wall displays, and agent scene queries read it; guarded `update_game` revises compatible rules/content without resetting earned progress |
| World display | `object.display` on an ordinary Matrix object | A world-space board renders authored text and can read game progress, gravity, one rigid body's live state, or a referenced object's pose, scale, and available local dimensions |
| World archives | Browser-local `matrix-web-world-archives-v1` store, separate from active browser/PC checkpoints and lost-AR-origin recovery archives | Reviewed list/new/restore actions archive the outgoing whole virtual world before switching and return bounded metadata and matching receipts |

The current registry includes `bridge` version `1.0.0` (`bridge-v1`), `curved-bench` version `1.0.0` (`curved-bench-v1`), and `staircase` version `1.0.0` (`staircase-v1`). The bridge's `riseMeters` generates a sloped deck; the bench has genuinely curved seat and back geometry; the staircase has individually indexed, closed treads with stable `step-01` through `step-12` part identities. Its `stepCount` is a bounded integer, checked in both the Web runtime and PC service before queueing or checkpoint writes. Each recipe is data, not executable source. A new generator requires ordinary reviewed source, tests, build, and deployment. Parameter edits to a loaded generator regenerate live. Generation is bounded to 32 parts, 4,096 vertices, 8,192 triangles, and 131,072 geometry buffer bytes. No Blender process or GLB export is needed for these constructions. The [isolated Agent Portal trace](../Validation/Procedural-Generator-Development-Desktop-2026-09-26.md) records the missing-generator observation, reviewed source/build, runtime reload, and receipt-backed creation and revision.

The current game rule vocabulary covers a delivered-count or score objective, a `release-near` or `sensor-enter` delivery rule, and an unlock consequence bound to existing exit object IDs. `update_game` requires the observed current spec and bindings. Once credit exists, it preserves the exact ledger, score, progress, and unlock; changed roles/rules or a changed win condition that cannot preserve that state require an explicit migration. Deleting a bound object, clearing its scene, or replaying incompatible scene history now fails before mutation. It is a reusable state/rule path for a challenge; arbitrary quests, conditional scripts, full walkable-surface navigation, and a general application UI framework are not established by this slice. A display is a readable world board, not a full HTML classroom or executable display program.

## Isolated browser and Operator acceptance route

Use a disposable browser profile and an isolated ControlService port, scenes directory, and web-assets directory. Do not point a test run at the user's active `8765` service or existing world. The server supports `--port`, `--scenes`, and `--web-assets`; configure the PC-local Codex Agent Portal in that isolated process using the existing reviewed launch path and a Python environment with its pinned MCP dependency. The normal `/web/` page and its local browser storage are the test surface. Verify that the connected Agent actually lists Matrix tools; an unavailable-tool report does not establish that the runtime lacks the capability. Read the connected `matrix_scene_summary` before each mutation and wait for the matching runtime receipt before treating it as applied.

1. Enter **Creator Mode** in `/web/` (desktop controls or the in-world Creator page). Ask: “Operator, create a physics playground with a ramp, three grabbable objects, a receptacle, an exit, and a wall display. Deliver all three objects to unlock the exit.” Use the generic procedural bridge with a nonzero rise for the ramp, normal Matrix objects for cargo/receptacle/exit, rigid configurations, a version-2 game bound to those IDs, and an `object.display` game-progress binding. Record each receipt and the observed object IDs. A visual ramp alone does not satisfy this step.
2. Enter **Play/Test Mode**. Observe the bodies settle and collide with the ramp and each other. Grab, move, and release one cargo object twice; each release must resume physical motion. Deliver each distinct object to the sensor, checking the same score on the board, desktop UI, and `matrix_scene_summary`. Re-entering the sensor or replaying an event must not award another point. The exit must show its unlocked state only after completion.
3. Return to **Creator Mode**. Revise the ramp's recipe, gravity, and board text/binding. Re-read the scene: the ramp and three cargo object IDs, game bindings, credited ledger, score, and unlock must remain compatible. Enter Play again to continue. Save the whole world, reopen the browser, rediscover the IDs/state through `matrix_scene_summary`, and make another supported edit.
4. Archive the first world, open a separate blank world, and build a **different interactive exhibit or classroom** from ordinary objects, using procedural construction where useful. For a dimensions experiment, bind a board to an object's transform, change its scale through a reviewed generic action, and verify that the board and Agent inspection report the same current dimensions. Other exhibits may instead use motion, gravity, or game state. Save, reopen, and revise the exhibit through the same scene, display, action, receipt, and checkpoint contracts; it must not depend on a second HTML simulation or a fixed exhibit template.
5. Record browser rendering and controls, exact runtime receipts, before/after scene summaries, save/reopen, failed/stale request recovery, and any PC whole-world restore separately from the automated tests. Repeat VR and AR controls/readability/grabs with a real headset before marking those mode-specific checks accepted.

## Persistence and physical-world limits

Browser world envelopes remain version 2 without Citizens and version 3 with Citizens. The merged implementation adds optional creator mode and gravity fields, while scene objects carry recipes, rigid configurations, and displays. Old saves without these fields restore to paused Creator Mode and default gravity. The game v2 ledger and exit unlock travel with the existing game field. The dynamic body's latest scene pose is saved; Rapier's transient velocities/contact cache are reconstructed on reopen, so exact in-flight velocity replay is not promised. A missing pinned generator version waits for recovery and leaves the prior world/browser copies intact. PC whole-world checkpoint validation must be run with the matching reviewed source and asset catalog; checkpoints do not contain generator source or GLB bytes. Ordinary world archives are a separate browser-local index, `worldSlotSchemaVersion=1`, with bounded metadata returned to the Agent; they are distinct from named PC checkpoints and AR-origin recovery archives. Switching requires paused Creator Mode and is guarded while a body is held, a pending command or PC checkpoint operation exists, or the world contains session-only physical AR objects; a failed archive leaves the active world intact.

WebXR AR may show and simulate **virtual** floor objects and their virtual colliders. No result here establishes a collider for a measured physical wall, table, or floor, or a verified headset room mesh. Browser and automated results must be reported apart from real VR/AR wearer results. The existing room-origin, approval, scoped authority, save recovery, and scene receipt gates remain in force.
