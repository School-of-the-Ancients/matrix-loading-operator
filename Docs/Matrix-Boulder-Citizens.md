# Matrix Boulder citizen prototype

This is a small local simulation in the dedicated [Matrix Boulder scene](../Assets/Sandbox/MatrixBoulder/Scenes/MatrixBoulder.unity). It starts two placeholder residents, Ada and Sol, with stable IDs. Each has a named home and workplace, a hunger and energy value, and a daily work interval. When hungry, a resident chooses the shared cafe. The prototype moves each resident toward its chosen point using a short geodetic test path. The HUD shows activity, needs, simulation time, and WGS84 coordinates. **Focus** moves the desktop fly camera above that resident; **Pause** stops the local clock.

Build and launch with `./Build-MatrixBoulder.ps1` and the setup in [MB-0](Matrix-Boulder-MB0.md). The prototype runs without a Cesium ion token, though city imagery requires one. One real second advances one simulated minute. The scene creates the residents on first launch, saves every 15 seconds and on pause/quit, and restores their IDs, positions, needs, destinations, and simulation time on the next launch.

The save is `MatrixBoulder/citizens-v1.json` beneath Unity's `Application.persistentDataPath`. It is versioned, separate from White Room / Room AR persistence, and contains latitude, longitude, **WGS84 ellipsoid** height, and heading rather than Unity-local transforms. An invalid or unknown-version save stops the prototype and is left untouched for inspection. To start over, move that file aside while the player is closed, then launch again.

The five locations are hand-authored elevated demonstration points near central Boulder. They are **not** road, address, terrain, or building data, and were not derived from Google's visual tiles. The bodies and tall beacons may float above imagery or pass through structures. They are deliberately visible placeholders until MB-2 provides independent open semantic and elevation data. Movement is a straight test path between nearby points; there is no collision, NavMesh, pedestrian routing, dialogue, GOAP, social behavior, or remote AI provider. The clock runs only while this desktop scene runs. The shared finite action executor and character assets in #13/#14 remain separate work under [AI NPC roadmap #29](https://github.com/School-of-the-Ancients/matrix-loading-operator/issues/29).

The next social slice can use the saved citizen IDs and observed activities to let nearby residents form a shared conversation. Keep action/state changes under deterministic local authority; optional model deliberation should propose bounded intentions and dialogue, with text and outcomes observable before adding spatial voice. This prototype makes no model calls or audio.

## Validation

`Build-MatrixBoulder.ps1` runs a deterministic editor check before building. It verifies that a resident chooses work and food, moves while retaining identity, that geodetic state survives JSON round trip, and that an unknown or missing vertical datum is rejected. The scene generator also checks its citizen component. The built player accepts `-batchmode -nographics -matrixBoulderSmoke` for a three-second startup/save smoke run; this uses `citizens-smoke-v1.json` so it cannot change the normal citizen save. A desktop build or headless smoke run does not prove live Cesium imagery, pedestrian ground alignment, or an always-running world service.
