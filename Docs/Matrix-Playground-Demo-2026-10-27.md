## The story

Choose one existing scene with a reliable interaction. The previously demonstrated rocket/spaceport, bridge, or simple dynamic-cube setup are candidates to inspect locally, not bundled assets promised by this runbook. Do not build a new city just to decorate this demo.

## Proposed 4-6 minute walkthrough

This is a rehearsal allocation, not an official time limit. Adjust to the instructor's slot.

| Beat | Action | Evidence to show |
| --- | --- | --- |
| Enter | Open the prepared world in the tested Quest mode. | Identify the live scene and briefly explain what is new. |
| Fast change | Select an available object, pin a fresh point, and request an ordinary move; alternatively place an already-registered asset. | Visible result and matching runtime receipt. Distinguish this from generating new geometry. |
| Interaction | Grab/release the tested dynamic prop, or use another already-supported interaction. | Actual response in the headset. Do not claim collision with a physical table from virtual-floor physics. |
| Deliberate edit | Resize or reposition the same prop; show a supported undo. Demonstrate scenery lock/unlock only if rehearsed. | Stable object identity, intentional control, unrelated scene preserved. |
| Persistence | Save, exit/reopen through the documented route, then inspect the same objects and supported interaction state. | The saved state really returns; a success message alone is insufficient. |
| Close | Summarize the measured improvement and one current limitation. | Brief preview of the professor/agent direction, clearly labeled future work. |

Any required mixed-reality/physical-room demonstration must be explicitly tested and shown. A VR walkthrough or browser screenshot does not establish AR alignment. Free placement must not be described as verified physical fit.

## Slow creation versus fast placement

Prefer a small live request that has rehearsed reliably. For Blender-heavy generation, either show its actual progress/time within the available slot or show a separately labeled recording followed by the completed live asset.

Label pre-generated/cached content and time compression clearly. Do not splice minutes of generation into an apparent seconds-long live result. Capture the actual original duration and settings. No new generation, paid provider use, or background refinement is launched by this document.

Measure at least these categories separately:

| Category | What to record |
| --- | --- |
| Existing-asset placement / ordinary edit | Submission, matching receipt, and visible completion; cold/warm condition; model/settings; errors and retries. |
| New procedural or Blender creation | Generation plus validation/import/placement, along with total user wait and any approval time. |
| Rendering and interaction | Actual headset/browser and scene; observable frame/performance limitations, input, readability, and comfort. |

Reuse [latency tracing](Latency-Traces.md). Several rehearsal timings are useful but do not replace #171's matched baseline/candidate suite. Publish raw sample counts and measurement limits; do not infer p50/p95 improvement from one successful edit.
